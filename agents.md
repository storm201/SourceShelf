# AGENTS.md — rules for anyone (human or AI agent) editing SourceShelf

Read this before changing anything. It exists because this project is
**live**: a scheduled GitHub Action writes to a real Supabase database and
publishes a real GitHub Pages site. A careless edit here does not show up as a
broken test — it shows up as wrong data on a public URL.

---

## 1. Never touch (requires the human's explicit approval)

| File / path | Why |
|---|---|
| `.env` | Live secrets (Supabase URL + service_role + anon keys). Never read it out loud, never commit it, never "tidy" it. It is gitignored for a reason. |
| `.gitignore` | Removing a line here is how `.env` or `cache/` leaks into a public repo. |
| `supabase/schema.sql` | Already applied to the live database. Editing the `create table` block without a real migration silently diverges code from the DB. `first_seen` semantics live here. |
| `.github/workflows/refresh.yml` | Production deploy path. It holds secrets wiring, `permissions:`, and the cron. A mistake here breaks data collection or page publishing, not just CI. |
| `tests/mock_supabase.py` | Test fixture. The `KEY` / `ANON` constants and the `Content-Range` behaviour are relied on by `test_supabase.py` and by page tests. |
| `data/apps.json` | Generated by the crawler. Hand-editing it is overwritten on the next run and can corrupt `first_seen`. |
| `data/apps.js` | Generated from `apps.json` by `build_single.py`. Same rule. |
| `data/config.js` | Generated by `build_single.py` from `.env`. The committed default is `window.__SUPABASE__ = null` on purpose. |
| `sourceshelf.html`, `dist/` | Build artifacts. Regenerate, never edit. |

If a change seems to require editing one of these, stop and ask. In practice the
answer is almost always "change a script, then regenerate".

---

## 2. Safe to change freely

These are the real source files, and where UI work belongs:

| File | What it is |
|---|---|
| `assets/app.css` | All styling. One file, no build step, no external fonts. It must work offline and inside a sandboxed iframe (no CDN, no `http://` assets — inline SVG or data URIs only). |
| `assets/app.js` | All front-end behaviour. Plain ES2019, no bundler, no npm. Runs from `file://` as well as `http://`. |
| `index.html` | The multi-file page. Keep the `id`s that `app.js` queries. |
| `RUN.md`, `START-HERE.md`, `DEPLOY.md`, `README.md` | Docs. Keep them beginner-shaped: numbered steps, each saying how to verify. |
| `scripts/*.py` | Crawler and tooling. Stdlib only — **do not add pip dependencies**; the workflow assumes zero installs. |
| `tests/test_supabase.py` | Add tests here for anything touching storage. |

## 3. Invariants the code already depends on

Break any of these and the site lies to its owner:

1. **`first_seen` is written once and never rewritten.** It is the only reason
   "new today" means anything. `push_catalog()` enforces this; do not "fix" it.
2. **A baseline run claims nothing is new.** If every discovery date is today
   there is nothing to compare against, so `seedRun`/`baseline` must suppress the
   arrivals strip and badge. Without this, day one announces 1,619 new apps.
3. **The catalog must never shrink.** A failed search query must not delete
   apps. `fetch_apps.py` retries failed searches, then carries over everything
   the database already knows. `--no-carry` exists but is a footgun.
4. **No fabricated numbers.** Star counts, download sizes and totals come from
   the crawl. Totals in the header come from Supabase's `Content-Range`, not
   from the page size we chose to render.
5. **No dead controls.** Every button, filter and link must do something real.
   If a feature is cut, remove the control too.
6. **Storage is honest.** The pill must say `Live · Supabase` only when a fetch
   actually succeeded, `JSON snapshot` when the build has no config, and
   `Fallback · JSON` when the fetch failed. Never fake "live".
7. **Supabase is real storage; `data/apps.json` is the fallback.** Both paths
   must keep working. Do not delete the fallback.

## 4. Before you call anything done

```bash
node --check assets/app.js          # syntax
python scripts/selftest.py          # expect: 0 failed
python tests/test_supabase.py       # storage contract
python scripts/build_single.py      # rebuild sourceshelf.html + dist/
```

Then render it — do not trust the diff:

- open the page (or `python scripts/serve.py`), check for console errors
- 1440px: three-across cards, sidebar, category tiles
- 390px: filters open from the ☰ button, cards stack
- click a card (drawer), a filter, a sort, and the `New arrivals` tab

Never report a UI change as finished without having looked at the page.
